# Working on tapbox

Open-source, screen-free NFC audio player for kids. Rust workspace; docs in `docs/`.

## Layout

- `crates/tapbox-card` — the open card format (`no_std` + `alloc`). Spec: `docs/card-spec.md`.
- `crates/tapbox-hw` — tag/reader layer (`no_std` + `alloc`). Drivers implement `Type2Tag`.
- `crates/tapbox-cli` — the `tapbox` developer CLI.
- `card-spec/vectors` — shared test vectors, generated by `card-spec/tools/generate_vectors.py`.

## Before every commit

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

## Rules

- Keep `tapbox-card` and `tapbox-hw` `no_std`. Hardware and OS specifics go in drivers behind traits.
- No `unsafe` (forbidden in the workspace). No `unwrap`/`expect`/`panic`/indexing outside tests.
- Card data is untrusted input: validate, bound sizes, never accept local paths.
- Never lock or format tags implicitly; both are irreversible.
- Changing the card format means: update `docs/card-spec.md`, the generator, the vectors, then the code.
- Prefer small, typed values (`WebUrl`, `ContentHash`) over raw strings across APIs.
- Doc comments on every public item; explain *why* in comments, not *what*.
- Raspberry Pi peripherals: use the standard Linux interfaces (`i2cdev`, `gpiocdev`, `linux-embedded-hal`), not `rppal` (archived July 2025).
